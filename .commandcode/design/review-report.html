// PRIORITY ISSUES
P1

R1 — No heading voice

Every heading on the surface is 16-17px. The largest thing is a 22px stat number. The hierarchy is upside-down — the section you're in should be louder than the data it contains.

FIX: /design typeset — add a display role (24px, 600 weight, -0.02em tracking) for panel headers. Add a heading role (18-20px) for section titles. Keep the 16-17px for the largest content blocks. The 22px stats get capped at 17-18px.
P2

R2 — Stat monument in Usage

Two oversized 22px bold numbers with no context. The most visually loud thing on the panel is the least meaningful.

FIX: /design refine — fold into a single line of copy. "128 enhancements · 47 with your own key" reads as a sentence and gives the numbers a story.
P2

R3 — Generic brand row

Rounded dark square + "Prompt Enhancer" + "v1" reads as a template. The wordmark is enough. The square and the version are decoration.

FIX: /design refine — drop the square. Drop the v1. Let the wordmark stand alone, sized as a display heading.
P2

R4 — Save bar steals attention without focus

When the save bar appears, keyboard users don't get moved to it. They have to find it. Visible bar but no programmatic focus.

FIX: /design interaction — when showSaveBar() runs, call .focus() on the save button. ~5 lines.
P2

R5 — Google Fonts blocks first paint

For an extension popup that opens dozens of times per day, a 100KB+ network font load on every open is the wrong trade. System fonts are visually close enough.

FIX: /design typeset — define a system-font-first stack (-apple-system, BlinkMacSystemFont, "Segoe UI Variable Display") with Geist as a face only if locally available. Zero network cost.
